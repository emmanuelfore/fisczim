# FiscalStack for Zoho Books

This directory is the source of the **FiscalStack for Zoho Books** extension.
After it is published and installed, the extension—not an administrator's
Zoho Books settings screen—owns the fiscalisation configuration:

- FiscalStack-style invoice receipt fields;
- a manual fiscalisation custom function;
- a fiscal invoice PDF template; and
- widgets in the invoice detail and invoice-list sidebars; and
- a **Fiscalise with FiscalStack** button on a pending invoice.

The installer enters only the FiscalStack base URL and a company API key in the
extension's configuration widget. They do not create custom fields, a custom
button, views, or a template in their Zoho organisation.

## Extension build contract

Create the extension once in the Zoho Books Developer Portal and add the
components described by [`extension-definition.json`](extension-definition.json).
This is publisher work, not tenant setup: Zoho provisions the declared
components each time the published extension is installed. Copy the Deluge
sources from `deluge/` into their named components and upload the widget ZIP
made from `widget/` (`zet validate && zet pack`).

The field and component placeholders generated by Zoho must be copied into
`extension-definition.json` before publishing. The source deliberately uses
symbolic placeholders (`{{...}}`) so no organisation-specific IDs are ever
committed.

## Required FiscalStack API surface

The extension calls only two API-key authenticated endpoints:

1. `POST /api/v1/fiscalize` to create the ZIMRA fiscal receipt.
2. `GET /api/v1/zoho-extension/qr-url?invoice_number=...` to obtain the signed
   public image URL placed in the invoice field.

The second endpoint is implemented in this repository and keeps the FiscalStack
company id and QR-signing key outside Zoho.

## Tenant experience

1. Install the marketplace/private extension.
2. In the extension setup form, paste the FiscalStack API base URL and that
   company's API key. The API key field is hidden after installation.
3. Open an invoice and select **Fiscalise with FiscalStack**. The extension
   writes the FiscalStack-style receipt fields and the supplied PDF template
   prints the QR and fiscal proof.

Fiscalisation is intentionally never automatic. The button is visible only
until `Fiscal Receipt Number` is populated, so the fiscalisation function is
idempotent and an already-issued ZIMRA receipt cannot be submitted again.

The `Fiscal Receipt Number` field is enabled as a list column and the list
sidebar widget shows a green **Fiscalised** or amber **Awaiting fiscalisation**
badge for every listed invoice. The PDF template prints the fiscal code, receipt
counter and number, fiscal day, ZIMRA device ID, verification code and URL,
status, date, and QR image, alongside complete seller/buyer, item-line, totals,
payment, and tax-summary sections.
