# FiscalStack connector for Zoho Books

This package contains two Zoho Books widgets:

| ZIP | Zoho location | Purpose |
| --- | --- | --- |
| `dist/FiscalStackSettings.zip` | `plugin.globalfields` | Connect FiscalStack, identify the Zoho Books organisation, show the registered company/device and recent fiscalised invoices. |
| `dist/FiscalStackInvoice.zip` | `invoice.details.sidebar` | Fiscalise the invoice currently open in Zoho Books, then show and print the fiscal receipt, QR code, fiscal day and verification data. |

Default FiscalStack API base URL: `https://fiscalstack.co.zw`

## Build the ZIP files

```bash
./pack.sh
```

The build creates `dist/FiscalStackSettings.zip` and `dist/FiscalStackInvoice.zip`. Both archives contain `plugin-manifest.json` and `app/` at the archive root, which is the layout Zoho expects.

If you change anything under `src/app/`, run `./pack.sh` again before uploading.

## 1. Create the FiscalStack API key

1. Sign in to the FiscalStack dashboard for the registered company.
2. Open the company API key settings and create or rotate the key.
3. Copy the key once. The key identifies the company and its registered ZIMRA fiscal device.
4. Do not put the key in source control or send it in chat.

The connector uses these FiscalStack endpoints:

| Endpoint | Use |
| --- | --- |
| `GET /api/v1/fiscal/device` | Validate the API key and read fiscal device status. |
| `GET /api/zimra/device-details` | Resolve the registered company, TIN, VAT number and device serial. |
| `GET /api/v1/invoices` | Read recent invoices and fiscal receipt metadata. |
| `POST /api/v1/fiscalize` | Submit the Zoho Books invoice to ZIMRA and return the fiscal receipt. |

All FiscalStack requests use the `x-api-key` header.

## 2. Upload the settings widget

This is the widget for the current **New Widget** screen (Configure > Global Fields > Upload Widget).

1. Enter the name `FiscalStack Fiscalisation`.
2. Enter the description:

   > Connect Zoho Books to FiscalStack for ZIMRA fiscalisation. Submit invoices for fiscalisation, retrieve official fiscal receipt details, synchronise fiscal information, and access QR codes and fiscal references for invoice printing.

3. Upload `dist/FiscalStackSettings.zip`.
4. Save.
5. Open the widget, enter the FiscalStack base URL (`https://fiscalstack.co.zw`) and the company API key.
6. Click **Test connection**, then **Save connection**.
7. Confirm that the registered company, device ID, device serial and fiscal day are displayed.

The API key maps to one FiscalStack company. If the customer has several registered companies, create a separate FiscalStack API key and a separate Zoho Books organisation connection for each company.

## 3. Create the invoice action widget

Create a second widget in the Zoho Books Developer Space:

1. Choose `invoice.details.sidebar` as the location.
2. Upload `dist/FiscalStackInvoice.zip`.
3. Install or refresh the extension in the Zoho Books organisation.
4. Open any invoice. The FiscalStack panel appears in the invoice sidebar.
5. If the panel says **Not connected**, use **Open connection settings** and enter the same API key.

The invoice widget reads the current invoice through the Zoho Finance SDK (`ZFAPPS.get("invoice")`), so it never asks for the Zoho Books password. Zoho Books handles the organisation context and OAuth session.

Before submitting, the widget:

- shows the invoice number, customer, date, total and line-item count;
- lets the user choose currency (`USD` or `ZWG`), payment method and tax treatment;
- warns when the invoice is a draft or a void/cancelled invoice;
- asks for confirmation before fiscalisation;
- handles duplicate invoice numbers by loading the existing FiscalStack receipt.

## 4. Zoho global field and connection (recommended for multiple users)

Without a Zoho global field, the connection is stored in the browser running the widget. To share the connection across all users and both widgets:

1. In the Zoho Books Developer Portal, open **Configure > Global Fields**.
2. Create a field named `FiscalStack Config`, data type **Text Box (Multi-line)**, visibility **Hidden** or **Read Only**.
3. Copy the generated placeholder, for example `vl__1234567_fiscalstack_config`.
4. In the Zoho Books Developer Portal, create a connection for Zoho Books with the scopes `Settings.READ` and `Settings.UPDATE`. Use the link name `fiscalstack_books` or update `src/app/config.js` with the link name you chose.
5. Copy the connection JSON generated by Zoho and paste it into the `usedConnections` array in both manifests.
6. Set `globalFieldPlaceholder` and `connectionLinkName` in `src/app/config.js`.
7. Run `./pack.sh`, re-upload both ZIP files, and install the extension again.

`src/app/config.js` contains:

```js
window.FISCALSTACK_ZOHO = {
  connectionLinkName: "fiscalstack_books",
  globalFieldPlaceholder: "vl__your_field_placeholder",
  apiBaseUrl: "https://fiscalstack.co.zw"
};
```

If either value is blank, the widget falls back to browser storage and the invoice widget shows its own connection panel. The Zoho connection is only used to read and write the Zoho global field. It is not used to access FiscalStack.

## 5. CORS

The widget runs in a Zoho-hosted iframe and calls `https://fiscalstack.co.zw` from the browser. The FiscalStack server must allow Zoho Books origins in CORS. This repository includes an allowlist in `server/index.ts` for Zoho-owned domains such as `books.zoho.com`, `books.zoho.eu`, `books.zoho.in`, `books.zoho.com.au`, `books.zoho.jp`, `books.zohocloud.ca` and Zoho CDN hosts.

If you host the widget on a custom domain, add that origin to the FiscalStack CORS allowlist and to the manifest's `whiteListedDomains` / `cspDomains` configuration.

## 6. Limitations in this starter

- Only `FiscalInvoice` is submitted. Credit notes, debit notes and bulk fiscalisation are not included yet.
- Tax treatment is inferred from Zoho Books tax names/percentages, with a manual override in the invoice widget. Review the tax mapping with the customer before production use.
- The invoice widget stores the last 100 fiscal receipts in browser storage. The full receipt remains available from FiscalStack.
- Zoho Books does not provide the buyer TIN/VAT in the standard invoice SDK payload used here, and the current FiscalStack fiscalise endpoint defaults the buyer to the walk-in customer. Add buyer mapping only after the FiscalStack customer flow is finalised.
- The API key is sensitive. Use a hidden Zoho global field, restrict who can configure the extension, and rotate the key if a device is lost.

## 7. Local validation

Install the Zoho Extension Toolkit if you want to validate with Zoho's own tool:

```bash
npm install -g zoho-extension-toolkit
cd build/settings && zet validate
cd ../invoice && zet validate
```

`zet run` can be used for local preview. The invoice widget needs the Zoho Books invoice context, so the final test must be done from an invoice detail page after installing the widget in a Zoho Books organisation.
